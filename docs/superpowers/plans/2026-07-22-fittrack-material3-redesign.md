# FitTrack 全局 Material 3 重构计划

**状态：** 方案讨论中。本文确认前，不继续进行 QML、React、资源或视觉基准的实现改动。

**目标：** 将 FitTrack 重构为 Android 优先、全局一致、可访问、可维护的 Material Design 3 训练应用。它必须像一个完整 App，而不是“系统默认控件加几张卡片”。

**实现基础：** Qt 6 Quick/QML、Qt Quick Controls Material、C++17、可选 React WebView 训练页。

---

## 1. 设计定位与范围

### 设计读法

这是面向长期训练者的高密度任务型移动应用。视觉应该克制、清晰、运动表现导向；训练期间优先呈现当前动作、当前组、重量次数和休息状态，不用营销页式装饰抢占注意力。

### 全局设计参数

| 参数 | 值 | 理由 |
|---|---:|---|
| 设计变化度 | 3/10 | 训练工具需要稳定、可预期，不做实验性布局。 |
| 动效强度 | 2/10 | 动效只反馈操作和状态迁移，不制造停留成本。 |
| 信息密度 | 7/10 | 训练数据密集，但用层级和留白保证可扫读。 |

### 明确纳入

- 全局 Material 3 色彩、排版、形状、状态和导航规范。
- 浅色、深色、跟随系统三种主题模式。
- QML 主端与 React 训练页共享同一份设计 Token。
- 首页、计划、训练准备、训练中、动作库、分析、历史、有氧、管理和全部弹层。
- 现有基础组件的重建或替换。
- ImageGen 生成的有限视觉资产。
- 触控、键盘、TalkBack、字体缩放、视觉回归和构建验证。

### 不纳入

- 重写业务规则、数据库、训练算法、导航信息架构或 C++ 控制器。
- 迁移到 Jetpack Compose、Flutter 或 Web-only。
- 在第一期启用 Android 动态壁纸取色。
- 为了“好看”生成按钮、输入框、图标或带文字的位图组件。
- 新增营销页式渐变、无限循环动效、装饰性玻璃效果或多套品牌色。

## 2. 技术路线

### 2.1 官方 Material 3 的定义

Material 3 官方规范是唯一视觉标准；`QtQuick.Controls.Material` 是跨平台运行时控件底座，不把 Qt 默认外观直接视作完整 M3 成品。

建立项目内 `FitTrack.Material` 组件层：

```text
M3 官方规范
    -> Theme / Typography / Motion Token
    -> FitTrack.Material 原子组件
    -> 页面组合
    -> 可选 React CSS Token 镜像
```

页面禁止继续自行组合颜色、圆角、阴影和字号。所有视觉选择通过 Token 或组件变体表达。

### 2.2 主题策略

- 第一阶段采用固定的 M3 Blue Seed 配色，保证品牌、截图和跨设备一致。
- 支持 `Light`、`Dark`、`System` 三套完整语义 Token。
- 动态壁纸取色作为后续可选偏好，默认关闭。
- Android 与 Windows 保持同一语义体系；Windows 允许更紧凑的布局，不缩小 Android 的触控目标。

### 2.3 字体策略

- 不打包新字体，继续继承系统字体和系统字体缩放。
- 原生 QML 不硬编码 `font.family`；Android 主要使用系统 Roboto 及中文回退字体，Windows 使用系统 UI 字体及微软雅黑回退。
- React 训练页改用与系统一致的字体栈，不依赖未打包的 Inter。
- 通过 Qt `fontInfo` 在 Android 与 Windows 记录实际解析到的字体、字重与字号。

## 3. 排版系统

### 3.1 单一来源

移除 `Theme.qml` 与 `Typography.qml` 的重复字号定义，保留一个 `Typography.qml` 作为唯一字号、字重、行高和数字特性来源。

### 3.2 M3 基础文字角色

| 角色 | 建议 | 使用场景 |
|---|---|---|
| Display | 32sp / 600 | 完成训练、重大结果。 |
| Headline | 28sp / 600 | 训练名称、关键状态。 |
| PageTitle | 22sp / 600 | 一级页面标题。 |
| SectionTitle | 16sp / 600 | 页面分区标题。 |
| Body | 16sp / 400 | 动作详情和长说明。 |
| BodyCompact | 14sp / 400 | 列表说明、训练参数。 |
| Label | 14sp / 500 | 按钮和表单标签。 |
| Meta | 12sp / 500 | 时间、辅助状态和导航标签。 |
| TableLabel | 11sp / 500 | 训练表格标题。 |

### 3.3 训练业务文字角色

| 角色 | 建议 | 使用场景 |
|---|---|---|
| MetricValue | 28sp / 600 / 等宽数字 | 容量、e1RM、最高重量。 |
| TimerValue | 32sp / 500 / 等宽数字 | 训练时长、休息倒计时。 |
| SetValue | 16sp / 500 / 等宽数字 | 重量、次数、组号。 |

### 3.4 中文字重和颜色约束

- 默认仅使用 400、500、600 三档字重；700 只允许在完成页或极强结果状态使用。
- 文本只使用 `onSurface`、`onSurfaceVariant`、`textTertiary`、disabled 四级语义色。
- 表格和计时数字开启 `tnum`，不依赖等宽字体。
- 页面最多同时出现四种文字角色，避免所有内容都抢主视觉。

## 4. 组件策略

### 4.1 不再被旧组件限制

现有组件不是设计约束。保留其业务绑定、ObjectName、无障碍语义和测试锚点，但当视觉结构不符合 M3 时，应重建组件，而不是在旧组件上叠加临时样式。

### 4.2 组件分级

| 类型 | 处理方式 | 说明 |
|---|---|---|
| Token | 重建 | Theme、Typography、Spacing、Motion。 |
| 基础交互 | 重建 | Button、IconButton、TextField、NumberField、Checkbox、Switch、ComboBox。 |
| 容器 | 重建 | Card、ListItem、Dialog、Bottom Sheet、Snackbar、Empty State。 |
| 应用壳 | 重建 | Top App Bar、Navigation Bar、页面布局与安全区。 |
| 训练专用 | 结构性重做 | SetRow、Timer Bar、当前动作面板、完成总结。 |
| 业务页面 | 组合迁移 | 保持数据源和路由，不保留旧视觉布局。 |

### 4.3 组件变体限制

| 组件 | 允许变体 |
|---|---|
| Button | Filled、Filled Tonal、Outlined、Text、Destructive。 |
| Card | Filled、Outlined、Elevated、Tonal。 |
| Text Field | Outlined 为默认，Filled 仅限紧凑表格。 |
| 弹层 | Dialog 用于确认，Bottom Sheet 用于编辑、选择和详情。 |
| 导航 | Material Navigation Bar，当前项使用容器型指示器。 |

不为单个页面创建只使用一次的“万能组件”，也不允许页面绕过这些组件直接写视觉样式。

## 5. ImageGen 视觉资产策略

### 5.1 用途

ImageGen 只生成增强品牌感和状态感的非功能视觉资产：

1. 首页无训练记录空态插画。
2. 计划为空或训练准备为空的状态插画。
3. 训练完成页的里程碑视觉背景或徽章插画。
4. 动作库或数据管理页的低干扰辅助视觉。
5. 用于设计评审的 3 至 5 张 M3 风格参考图，不直接进入应用。

### 5.2 禁止用途

- 不生成图标、按钮、输入框、导航项、信息图标或文字。
- 不生成涉及动作教学准确性的解剖、器械或训练姿势替代图；现有已审核动作图继续使用。
- 不生成带中文文字、数字、品牌标识或不可本地化信息的图片。

### 5.3 资产规范

- 统一使用固定 Blue Seed、冷中性色、低饱和运动摄影或抽象器材语言。
- 每个资产都有明确屏幕、尺寸、用途和暗色模式处理方式。
- 资源需本地化打包，保存生成提示词和来源说明。
- 使用前先导出 Contact Sheet 供人工筛选；不接受“生成了就使用”。

## 6. 六轮执行计划

每轮结束都提交可独立回滚的 Git commit，并进行一次设计评审。下一轮只在当前轮确认后开始。

### Round 1：基线与设计冻结

**目标：** 确定唯一 M3 方向，并清理不可靠的实现基线。

- [ ] 对比 `e943351` 与当前 Material 分支，明确哪些未批准视觉提交需要保留或回退。
- [ ] 输出现有 UI 审计：重复卡片、重复 Token、乱用字重、非 M3 控件、视觉测试锚点。
- [ ] 确认固定 Blue Seed、主题模式和字体策略。
- [ ] 生成仅用于讨论的 M3 参考板，不修改 App 资源。
- [ ] 建立每页的文字角色映射表。

**完成条件：** 用户确认视觉方向、主题策略、排版角色和 ImageGen 用途。

### Round 2：全局 Material 3 基础

**目标：** 让任何页面都能从一套正确的基础系统开始。

- [ ] 合并 Theme 与 Typography 的职责，建立 Light、Dark、System Token。
- [ ] 建立形状、间距、海拔、焦点、禁用态和动效 Token。
- [ ] 设置 Qt Material 主题、容器样式和 Android/Windows 变体策略。
- [ ] 建立实际字体解析日志或开发检查页。
- [ ] 为 React 输出同名 CSS Variables。

**完成条件：** 不存在重复字号来源；无页面直接定义品牌 Hex；主题切换无明显缺失状态。

### Round 3：基础组件与开发体验

**目标：** 消除对丑旧组件的依赖，让后续页面开发有正确工具。

- [ ] 重建 Button、IconButton、TextField、NumberField、Checkbox、Switch、ComboBox。
- [ ] 重建 Card、ListItem、Dialog、Bottom Sheet、Snackbar、Empty State。
- [ ] 重建 Top App Bar、Navigation Bar、App Page Shell。
- [ ] 保留既有 ObjectName、Accessibility 名称和业务信号；仅改变视觉组件实现。
- [ ] 编写简短组件用法文档和禁止事项。

**完成条件：** 新页面不必复制样式代码；组件在 1.0、1.3、1.5、2.0 字体缩放下可用。

### Round 4：首页、计划与训练准备

**目标：** 建立日常打开应用时的完整产品感。

- [ ] 重构首页为“今日训练、近期进度、最近活动”三级信息结构。
- [ ] 重构计划页，收敛卡片嵌套和重复操作按钮。
- [ ] 重构训练准备页，主操作固定为开始训练，编辑操作进入 Bottom Sheet 或菜单。
- [ ] 审核并接入第一批通过筛选的空态视觉资产。

**完成条件：** 每屏只有一个 Filled 主操作；页面不再由无差别白卡片堆叠组成。

### Round 5：训练中与训练完成

**目标：** 优先完成真实训练时最关键、最复杂的体验。

- [ ] 重构训练 Top App Bar、进度摘要、当前动作和组表。
- [ ] 采用 `MetricValue`、`TimerValue`、`SetValue` 区分核心数字。
- [ ] 重构休息计时为固定可见的 Material Bottom Action Bar。
- [ ] 重构训练完成总结、短休追加、已完成组编辑和错误反馈。
- [ ] 审核触控、单手操作、键盘焦点、TalkBack 和大字体。

**完成条件：** 用户能在不滚动寻找关键操作的情况下完成当前组、暂停休息和结束训练。

### Round 6：长尾页面、React 一致性与交付

**目标：** 让 Material 3 贯彻全应用，并建立可持续维护的验证体系。

- [ ] 迁移动作库、动作详情、分析、历史、有氧和管理。
- [ ] 对 React 训练页应用同名 Token 和文字角色，不重复创造样式体系。
- [ ] 生成并审查第二批非功能视觉资产。
- [ ] 修复或隔离 `qmlnavigation` 视觉测试执行问题。
- [ ] 在受控环境重新生成并人工确认视觉基准。
- [ ] 运行 QML lint、构建、自动测试和视觉回归。

**完成条件：** 全局主题一致、关键流程可访问、所有基准更新有人工确认、没有未解释的视觉例外。

## 7. 验收标准

### 设计

- 每页仅有一个 Filled 主操作。
- 页面不直接使用原始 Hex、随意字号、随意圆角或任意阴影。
- 相同语义在任意页面使用相同组件、字号、字重和颜色角色。
- 训练页重点信息在首屏可见，辅助操作不抢主视觉。
- ImageGen 资产为状态与氛围服务，不能代替功能组件或信息文本。

### 可访问性

- 触控目标至少 48dp。
- 全部交互项有可读的 TalkBack 名称。
- 键盘焦点可见，弹层无焦点陷阱。
- 所有状态同时使用文字、图标或形状，不单靠颜色。
- 1.0、1.3、1.5、2.0 字体缩放下无标题截断和主操作溢出。

### 工程

- 业务控制器、数据库、数据结构和导航入口保持不变。
- 不保留重复 Theme/Typeface 定义。
- QML lint、Windows 构建、自动化测试和视觉基准在受控环境通过。
- 每轮只提交本轮必要文件，不顺手重构无关业务代码。
