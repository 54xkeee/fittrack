# FitTrack Android 开发计划

> 2026-07-14 新增的训练启动、动作预览、参数恢复、排序、性能和 UI 重构，以 [`fittrack-interaction-ui-performance-refactor-plan.md`](fittrack-interaction-ui-performance-refactor-plan.md) 为当前执行计划。旧里程碑中标记“已完成”但缺少真实交互或真机证据的项目，需要按新计划重新验收。

## 1. 目标与冻结边界

FitTrack 是一个全新的 Android 个人健身训练记录应用，位于现有仓库的 `fittrack/` 子目录，不复用或修改原有成绩管理系统业务代码。当前交付目标是供用户长期自用并可直接分享 APK 给其他用户安装；应用商店上架是可选后续阶段。

首版完整覆盖 PRD：谭成义三分化、自由训练、动作替换与排序、组记录、短休追加组、后台休息计时、动作资料库、力量与容量分析、有氧记录、健身房与器械、备份恢复。

明确不做登录、云同步、饮食、社交、自动训练计划、自动重量建议、RIR/RPE 和复杂周期化算法。

## 2. 技术基线

- UI：Qt 6.9、Qt Quick/QML、Qt Quick Controls Material
- 业务逻辑：C++17
- 构建：CMake + Ninja
- 数据库：SQLite（Qt SQL）
- 测试：Qt Test；核心计算与仓储优先自动化测试
- Android：`arm64-v8a`，以一加 Ace 5 Pro 等现代竖屏手机为主测设备
- Android 包名：`com.fittrack.app`
- 数据策略：离线优先，动作与模板由版本化 JSON 种子导入 SQLite
- 媒体策略：58 个系统动作各使用 1 张已审核的可分发图片；42 张为开放许可/公共领域素材，16 张为 FitTrack 原创 CC0。国内视频平台截图、MuscleDB 授权不明图片和旧图片目录不进入 APK

### M0：工具链与空应用

- 安装 CMake、Ninja、Qt Declarative/Quick、Qt Android 套件、Android SDK/NDK/JDK。
- 创建 CMake/QML/C++ 项目，桌面调试版和 Android `arm64-v8a` 均可构建。
- 显示 Material 深色空首页，并建立统一日志输出。

验收：桌面调试程序启动；一加 Ace 5 Pro 安装 APK 并进入首页。

### M1：核心领域模型和统计

- 定义动作负重模式：普通重量、单只哑铃、单侧，以及自重动作的纯自重/附加负重/辅助重量三种记录语义。
- 定义训练会话、训练动作、正式组、短休追加组。
- 实现训练容量、最高重量及对应次数/组数、Epley e1RM。
- 对空数据、未完成组、自重组、哑铃双手动作、单侧双边动作编写测试。

验收：统计规则全部通过自动化测试，不依赖 UI 或数据库。

### M2：SQLite 与种子数据

- 建立数据库迁移和版本表。
- 建立动作、肌群、媒体、替代动作、收藏、计划、训练记录、有氧、健身房和器械表。
- 导入只读系统动作与谭成义 Push/Pull/Legs 原版模板。
- 系统数据可恢复默认，且不删除用户动作、个人计划和历史记录。

验收：全新安装自动建库；重复启动不重复导入；恢复默认数据不破坏用户数据。

### M3：训练计划和自由训练

- 展示只读三分化原版并支持复制为个人版本。
- 支持计划、训练日、动作分组命名。
- 支持添加、替换、删除动作，以及三种场景的拖动排序。
- 支持“重量 × 次数 × 组数”快速生成组卡。

验收：可从三分化或空白自由训练创建可执行训练快照，原版模板始终不被修改。

### M4：正式训练与休息计时

- 每组保存重量、目标次数、实际次数、完成、力竭和备注。
- 允许用户逐组修改目标次数；该入口不生成重量或次数建议。
- 支持短休追加组；完成组后立即持久化。
- 显示同动作、同器械的上次记录，但不自动填入。
- 实现 2/3/5 分钟、自定义、暂停、继续、重置、提前结束。
- 桌面窗口最小化或进入后台后按绝对截止时间继续计时，恢复前台时校准，到时播放一次提示音。
- Android 使用前台服务和系统通知维持后台倒计时，完成时只提醒一次；仍需真机验证锁屏和 ColorOS 后台行为。
- 支持异常退出后的未完成训练恢复。

验收：杀掉并重启应用后已完成组不丢失；后台计时真机准确。

### M5：动作资料库

- 当前已整理 58 个目标动作，覆盖原动作库、用户明确列出的三分化动作和焚诀跟练动作，不导入 MuscleDB 全部 873 项。
- 每项动作统一展示 1 张已审核的本地动作图。29 项清单动作采用用户原文的发力要点、注意事项与常见错误；清单外旧动作只替换 MuscleDB 能明确提供的文字字段，保留既有训练参数。58 张图片由 42 张开放素材和 16 张原创 CC0 图组成，动作详情显示标题、来源和许可证。
- 内置动作只读、可收藏、可恢复；用户动作可新增、编辑和删除。
- 按肌群、动作模式、器械、三分化/焚诀动作集合、健身房可用性和收藏组合筛选。
- 使用校验工具检查唯一 ID、别名冲突、媒体许可、替代关系和必填字段。

验收：所有种子数据通过结构校验；离线可查看文字与本地图片；每个系统动作恰好 1 张可分发图片；未授权视频、MuscleDB 图片和旧图片目录不进入 APK。

### M6：分析与可视化

- 首页展示滚动 7 天统计卡片。
- 分析页支持 7 天、30 天、全部历史。
- 单动作已展示最高重量、对应次数、该重量组数、e1RM、训练容量趋势。
- 总体展示正式组数、训练时长、肌群主要/次要参与组数和有氧时长。
- 固定器械支持按健身房和器械实例筛选，避免不同机器数据混用。

验收：无数据时显示空状态；图表可触摸查看日期和数值；统计结果与数据库测试样本一致。

### M7：有氧、器械与备份

- 爬坡机默认模板：坡度 9、速度 5 km/h、30 分钟；距离和平均心率选填。
- 爬楼机记录等级、时长、层数/步数和平均心率。
- 有氧可单独开始或附加到刚完成的力量训练；个人训练日可保存一个跑步机或爬楼机目标，开始训练时复制快照，训练后仅预填实际表单。
- 管理健身房、器械名称/编号/备注。
- 支持导出数据库、JSON 备份和恢复；v4 JSON 包含计划有氧和训练快照，并兼容缺少这两张表的旧备份。

验收：空字段保持 `NULL`；备份恢复前后关键表数据一致；有氧、器械和备份集成测试通过。桌面部分已于 2026-07-13 验收。

### M8：直接分发与答辩

- 完成全量 Stitch 视觉、空状态、Safe Area、启动页、Adaptive Icon 和演示数据。
- 实现 Android 前台计时服务、通知、SAF 备份恢复、系统返回键和应用生命周期适配。
- 执行单元测试、SQLite 集成测试、QML 页面测试、升级迁移测试和 Android 真机回归。
- 准备简明隐私说明、医疗免责声明、第三方许可和媒体来源清单；当前仓库已提供完整许可正文与自动打包入口，正式分享时必须使用脚本生成的配套材料。
- 使用长期密钥生成签名 Release APK，并准备版本说明、安装说明和 SHA-256；AAB 与商店物料留作可选后续工作。

验收：一加 Ace 5 Pro 完整训练流程、后台计时、备份恢复和升级安装通过；核心演示无崩溃、无数据丢失、无未授权内置媒体，发布材料与应用真实行为一致。

## 5. 动作资料并行流水线

动作内容可由多个子代理并行整理，但必须按肌群分包，最后统一校验：

1. 胸肩三头；
2. 背部二头；
3. 臀腿；
4. 三分化原视频核对与媒体许可；
5. 主代理统一中文名称、别名、肌群枚举和 JSON schema。

抖音、B站、知乎内容只作为教学研究和外链候选；只有自制、明确授权或开放许可片段可内置。

## 6. 实施顺序与提交策略

严格按 M0 → M8 推进。每个里程碑先写可失败测试，再实现最小功能，通过后提交。动作资料可以与 M1—M4 并行制作，但只在通过数据校验后合入。

### 阶段门禁

进入任何下一开发阶段之前，必须先向用户说明并确认：

1. 最终产品目标是否变化；
2. 当前已经完成的能力；
3. 当前缺口和依赖关系；
4. 下一阶段包含与明确不包含的范围；
5. 下一阶段验收标准。

只有用户确认后才能开始该阶段开发。完成当前阶段不代表可以自动进入下一阶段。

当前阶段为 R6 完成度审计与真机验收，不新增训练建议等业务边界。训练恢复 ≤5 SQL、合成旧库迁移与损坏恢复、5 状态视觉基准和许可侧载包的桌面门槛已经关闭；剩余项目为一加 Ace 5 Pro 的安装、后台计时、通知、SAF、返回键、异常恢复、真实 TalkBack、系统大字体和数字键盘，以及真实历史 v1–v7 数据库升级与损坏库恢复、发布签名和覆盖升级证据。58 个动作目前各有 1 张可分发图；最初“两张 MuscleDB 起止图”目标仍需用户在接受单图与提供分发授权之间明确选择。
